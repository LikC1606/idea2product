## 【CRITICAL】前端代码必须严格遵循 api_specs
前端发送数据时，必须严格按照 api_specs 中定义的 request 字段和类型生成代码：

1. **字段名必须完全一致**：
   - api_specs 定义了 `author_id: "int"`，前端就必须发送 `author_id`
   - 不能省略任何必填字段！

2. **字段类型必须完全一致**：
   - `"bool"` → JavaScript `true`/`false`（不是字符串 "true"/"false"）
   - `"int"` → JavaScript 数字（如 `parseInt(value)` 或 `Number(value)`）
   - `"array"` 或 `["str"]` → JavaScript 数组（如 `["tag1", "tag2"]`）

3. **【强制】关联 ID（如 author_id）必须从 session 获取**：
   - 如果 api_specs 的 request 中需要 author_id，后端从 session 获取
   - 前端不需要传递 author_id，后端自己从 session['user_id'] 读取
   - 例如：创建博客时，后端用 session.get('user_id') 获取当前用户ID

4. 数据格式：所有 API 用 JSON，禁止用 FormData

## 【CRITICAL】Session 认证实现
如果 api_specs 中的 endpoint 有 session_info 说明，必须按要求实现：

1. **后端设置 session**：登录成功后设置 session['user_id'] = user.id（或其他 session_info 指定的变量）

2. **后端获取当前用户**：提供 /api/auth/me 端点，从 session 获取用户ID并返回用户信息

3. **确保 app/__init__.py 设置了 secret_key**：app.secret_key = 'your-secret-key'

## Code Correctness Rules (MUST FOLLOW)

1. **Imports MUST match actual modules**：
   - 所有 `import` / `from ... import ...` 必须引用真实存在的模块或符号；
   - **禁止**凭空创建不存在的模块名或从未定义的符号；
   - 对于应用内部模块，优先使用 `app` 包中的已有文件（例如 `app.routes.*`, `app.models.*`）。
2. **Respect interface-first contracts**：
   - 函数/方法的参数和返回类型 **必须**与 `.pyi` stub / InterfaceSpec / Skeleton 中的签名保持一致；
   - 不要随意改变返回类型（例如把 `List[str]` 改成 `str`），宁可先返回简单但类型正确的实现。
3. **Prefer safe fallbacks over guessing**：
   - 如果你不确定如何实现某个复杂逻辑，**宁可**使用安全占位实现（例如 `raise NotImplementedError` 或最小可用逻辑），也不要生成看起来复杂但容易出错的代码；
   - 当需要调用其他模块中的函数时，先对照已给出的接口签名（Skeleton / symbol_table），避免猜测参数顺序或名称。
4. **External resources must be wrapped and validated**：
   - 对文件、网络请求、数据库访问使用清晰的封装函数，并添加基本错误处理（try/except）；
   - 确保在异常路径下不会悄悄吞掉错误（记录日志或抛出合适的异常）。
5. **Do not ignore obvious errors**：
   - 若在阅读现有文件时发现明显错误（比如未使用的导入、死代码、无法到达的分支），在完成当前任务前一并修正；
   - 避免引入新的 `bare except`、未使用变量、重复逻辑等会增加 bug 风险的模式。
