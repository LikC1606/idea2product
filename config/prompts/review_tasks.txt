## 审查要点
请从以下通用维度审查（适用于任何类型的应用）：

1. **功能覆盖**：逐条对照上面的 Features 列表，检查每个 feature 是否被至少一个任务覆盖。
   - 列出每个 feature 对应的任务 ID
   - 标记未被覆盖的 feature

2. **实体完整性**：从需求中识别所有数据实体（如用户、订单、商品等），检查：
   - 每个实体是否有对应的后端任务（模型 + API）
   - 实体之间的关联关系是否在描述中体现（如外键关联）

3. **CRUD 完整性**：对于每个数据实体，检查是否包含必要的增删改查操作。

4. **前后端对应**：
   - 每个需要用户交互的 feature 是否有对应的前端任务
   - 前端任务是否正确声明了对后端任务的依赖

5. **依赖关系检查**：
   - dependencies 是否形成有向无环图（无循环依赖）
   - 是否有遗漏的依赖（如前端任务缺少对后端任务的依赖）

6. **一致性**：
   - 任务描述与需求是否匹配
   - 任务之间是否有遗漏或重复

7. **Auth 任务完整性**（当任务涉及登录/认证时）：
   - 若任何任务涉及「登录 / login / 用户认证」，必须存在实现「注册 / register」的任务
   - 认证相关任务描述需同时覆盖 register 与 login（POST /api/auth/register、POST /api/auth/login）
